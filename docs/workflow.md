# 任務處理流程與難度分級

## 流程

1. 提出需求 → 2. AI 判斷任務難度、分配模型 → 3. 解決任務 → 4. AI 自我審核是否需修改 → 5. 完成 → 6. 交給使用者審核 → 7. 審核檢討並記錄 → 若未通過回到步驟 3，直到使用者確認完成。

## 任務難度分級（草案，之後可依實際使用調整）

| 等級 | 說明 | 範例 |
| --- | --- | --- |
| 簡單 | 單一步驟、資訊明確、無需外部資料 | 格式轉換、簡短問答 |
| 中等 | 需要多步驟或少量資料查找 | 整理清單、簡單腳本 |
| 複雜 | 需要跨資料來源整合、長流程或需人工決策點 | 專案規劃、跨系統整合 |

## 任務分類

任務第一層固定分兩大類：

- `tasks/工作/`：工作相關的任務
- `tasks/個人/`：除了工作以外的任務，全部歸類在這裡

之後若某一類任務變多，可以在該分類底下再依需要建立次分類（例如 `tasks/個人/財務/`、`tasks/工作/專案A/`），但第一層固定就是這兩類。

## 記錄規則

每次審核完成後，於 `tasks/` 對應任務檔案中記錄：
- 審核日期
- 審核結果（通過 / 需修改）
- 修改建議（若有）
- 最終確認日期
