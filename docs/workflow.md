# 任務處理流程與難度分級

## 流程

1. 提出需求
2. AI 判斷任務屬於工作或個人，並到 `workflow/` 對應分類底下比對是否有相符的既有流程
   - 有相符流程 → 套用該流程，必要時做微調
   - 沒有相符流程 → 依 `workflow/template.md` 的格式新增一份流程文件，存入 `workflow/`，供之後同類任務判斷使用
3. AI 判斷任務難度、分配模型
4. 解決任務
5. AI 自我審核是否需修改
6. 完成，交給使用者審核
7. 審核檢討並記錄 → 若未通過回到步驟 4，直到使用者確認完成

## 流程庫（workflow/）與任務紀錄（tasks/）的分工

兩者用途明確分開，不要混放：

- `tasks/`：只記錄**已完成**的任務結果——做了什麼、最終結果、使用者的審核結論。是任務的「成果存檔」。
- `workflow/`：記錄**流程本身**——怎麼做、規則、以及流程的修改記錄。每次流程有調整（新增步驟、修正做法、規則變更），都寫進對應流程文件的「版本記錄」欄位，不要寫進 `tasks/`。

簡單說：某件事「做完了、結果是什麼」→ 寫 `tasks/`；「這類事以後該怎麼做、規則變了」→ 寫 `workflow/`。

```
workflow/
├── template.md          新增流程時的格式範本
├── work/                工作類任務的流程
└── personal/            個人類任務的流程（依任務類型再分檔）
    └── reservation.md   找餐廳並訂位
```

判斷邏輯：
- 收到新任務時，先看任務屬於工作還是個人，到對應資料夾裡找有沒有情境相符的流程文件
- 找得到但不完全吻合 → 依現況微調後使用，且視情況更新該流程文件（記得在版本記錄留下修改原因）
- 完全找不到相符流程 → 複製 `workflow/template.md`，依任務內容填寫後存入對應分類資料夾，往後同類任務就能直接比對套用
- `work/`、`personal/` 底下依實際任務類型建立個別檔案（例如訂位相關任務都歸到 `personal/reservation.md`），不要把所有流程擠在同一份文件裡

## 任務難度分級（草案，之後可依實際使用調整）

| 等級 | 說明 | 範例 |
| --- | --- | --- |
| 簡單 | 單一步驟、資訊明確、無需外部資料 | 格式轉換、簡短問答 |
| 中等 | 需要多步驟或少量資料查找 | 整理清單、簡單腳本 |
| 複雜 | 需要跨資料來源整合、長流程或需人工決策點 | 專案規劃、跨系統整合 |

## 任務分類

任務第一層固定分兩大類：

- `tasks/work/`：工作相關的任務
- `tasks/personal/`：除了工作以外的任務，全部歸類在這裡

之後若某一類任務變多，可以在該分類底下再依需要建立次分類（例如 `tasks/personal/finance/`、`tasks/work/projectA/`），但第一層固定就是這兩類。

## 記錄規則

每次審核完成後，於 `tasks/` 對應任務檔案中記錄（這是已完成任務的成果紀錄，不是流程規則）：
- 審核日期
- 審核結果（通過 / 需修改）
- 修改建議（若有）
- 最終確認日期

若這次任務過程中發現流程需要調整（例如做法要改、多了一個步驟、規則要更新），改的地方寫進 `workflow/` 對應流程文件的「版本記錄」欄位，不要寫進 `tasks/` 的任務檔案裡。
